# SmartHR Interview Guide

## Overview

SmartHR 면접에서는 HR 도메인, 프로덕트 품질, 사용자 가치, 팀 개발 문화와 본인의 HRMS 경험을 연결하는 것이 중요하다.

---

## Fit with My Experience

| My Experience | SmartHR Fit |
|---|---|
| HRMS 프로젝트 | HR 도메인 이해 |
| 勤怠管理システム | 업무 규칙과 사용자 흐름 이해 |
| Spring Boot / React | Web application development |
| 리더 경험 | 팀 개발, 코드 리뷰, 진행 관리 |
| AI 개발 프로세스 | 생산성・품질 개선 가능성 |

---

## Expected Questions

- なぜSmartHRに興味を持ちましたか。
- HR領域での開発経験について教えてください。
- ユーザーにとって使いやすい業務システムとは何だと思いますか。
- 品質と開発スピードのバランスをどう考えますか。
- チーム開発で大切にしていることは何ですか。

---

## Japanese Model Answer

```text
御社に興味を持った理由は、SmartHRが人事・労務という多くの企業にとって重要な業務領域を、
プロダクトの力で継続的に改善されている点です。

私自身も社内HRMSプロジェクトで、勤怠管理システムのリニューアル開発に携わり、
認証機能、管理者機能、Web API、バッチ処理、開発プロセス改善を経験しました。

その経験から、HR領域のシステムでは、業務ルールの正確性だけでなく、
利用者が迷わず使えること、変更に強い設計にすることが重要だと感じています。

これまでの業務システム開発経験と、AIを活用した開発プロセス改善の経験を活かし、
プロダクトの品質とチームの生産性向上に貢献したいと考えております。
```

## Reverse Questions

- SmartHRのバックエンド開発で、現在特に改善したい技術課題は何でしょうか。
- HR領域の複雑な業務ルールを、開発チームではどのように共有されていますか。
- コードレビューでは、どのような観点を特に重視されていますか。
- AIを開発プロセスに活用する取り組みはありますか。
- 入社後、バックエンドエンジニアに最初に期待される役割は何でしょうか。

---

## Checklist

- [ ] HRMS 경험과 SmartHR의 HR 도메인을 연결한다.
- [ ] “業務ルールの正確性”을 강조한다.
- [ ] AI 이야기는 품질・생산성 개선으로 조절한다.
- [ ] 제품 사용자를 의식한 답변을 준비한다.
